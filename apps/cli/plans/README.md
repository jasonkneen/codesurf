## Findings considered and rejected

- **Duplicate dependencies (two AI SDK layers, MCP SDKs)**: rejected — the
  AI-SDK packages are complementary layers (core + per-provider adapters +
  distinct integrations), `@ai-sdk/mcp` vs `@modelcontextprotocol/sdk` is a
  deliberate client-vs-protocol-types split documented in
  `src/mcp/runtime.ts`. Not duplication.
- **Dead-code sweep**: rejected as a workstream — a targeted sweep found only
  ONE dead export (`getModeSpecificModel`, handled in plan 005). The repo is
  not carrying meaningful dead code; effort goes further on duplication.
- **"One base class for all providers"**: rejected — the big provider
  sessions (claude-agent SDK queue vs desktop HTTP job-poll vs omnigent SSE)
  genuinely differ in control flow; forcing a base class would be
  over-abstraction. Shared LEAF helpers (plans 004/006, backlog
  DEBT-02/05/09) are the right altitude. Realistic consolidation ceiling for
  the cluster: ~15–18% (~1,400–1,700 lines), not half.
- **Re-litigating the app.tsx god component**: rejected — already fixed
  (7,300 → 566 lines, provider tree per REFACTOR_PLAN.md); streaming token
  path verified clean (stream-store isolation, memoized providers, bounded
  tail preview). Remaining UI cost is the chip subtrees (plan 002).
- **Evidence correction recorded during vetting**: PERF-20's "per-edit
  settings read" is anchored at `file-tools-approval.ts:29-37,62` (the
  `file-tools.ts:142` cite was the `/edits` command handler, not the per-edit
