## 1. Why this exists

Codesurf capability today is scattered across codebases that each re-implement the same engine:

| Codebase | Role | Status |
|---|---|---|
| `grok-cli` (jasonkneen/codesurf-cli) | CLI agent (TUI, OpenTUI), Cordis plugin host, headless | **Canonical engine home** |
| `~/clawd/collaborator-clone` (jasonkneen/codesurf) | Electron codesurf IDE ("collaborator", ex-"conduit", ex-daemon-sans-TUI) | **Client/front** |
| `agensis-agent` | WS relay daemon shelling out to external CLIs | **Relay role** (to embed the engine) |
| `deepseek-harness` | DSH engine (CLI + web GUI, Cordis, PTC) | Capability source; a front/instance of the same engine |
| `agensis.io` / `legion` | Hub/workspace products | **Hubs are a role, not a product** |
| `cascade`, `conduit` | Older concepts | **NOT architecture drivers** (may evolve; ignore for design) |

The pain: every new surface threatens to re-fork the harness. The cure: **one engine, many roles** — a single package that, depending on how it is launched, is a TUI client, an agent gateway (server), a relay node, a hub, a data node, or a device-resident agent. Nothing else is ever built from scratch again.

## 2. Vocabulary (normative)

| Term | Meaning |
|---|---|
| **Engine** | The codebase (`grok-cli`). All roles are this package in a launch mode. |
| **Agent gateway** | The codesurf `server` role: hosts sessions, tool plane, PTC presentation, worker runtime; exposes the wire to fronts and peers. (Do NOT confuse with LLM gateway.) |
| **Relay** | Transport role between sites; outbound authenticated WebSocket (agensis-agent precedent). Files/tools traverse it bounded (see §7). |
| **Hub** | Directory + presence + routing + ACL role. Holds **zero data**. Any node can act as hub (agensis.io, legion, a laptop). The protocol is the product, not the hub. |
| **Front** | UI consuming a gateway/hub: codesurf TUI, codesurf IDE, agensis web/desktop, legion, DSH web. |
| **Agent** | An addressable executor with a capability set and stable ID — server-resident or device-resident (Remarkable Pro, Android phone, DGX Spark, bunker VM). Appears in the hub directory; `@`-tag addressing surfaces it anywhere. |
| **Data node** | Node that owns skills/context/memories/source. Serves them bounded; never ships raw content off-node. |
| **LLM gateway** | Inference pool: multiplexes provider keys/accounts, ceilings, fair queue, per-tenant telemetry (Hermes `:8642` precedent generalized). |
| **Steward** | Always-on policy gate on tool dispatch (authz, redaction, scope, audit). |
| **Q** | Quartermaster: broker *agent* that reads an incoming task, decides what the executor needs, tools the executor up, supervises, returns the distilled result. Runs near the data; invoked by policy (§8). |

## 3. Principles (the rules that end duplication)

1. **Anti-duplication law.** A capability lives once, in the engine. A new surface is a front/role of the same package — never a new harness. "A version for IDE X" is a design error.
2. **Protocol is the product.** The registry/presence/delegation wire is the crown jewel, not any hub or UI.
3. **Data stays where it lives.** Content crosses boundaries only as bounded envelopes (§7) — summaries, anchors, handles. `expand` fetches more under the same gate.
4. **Hub holds nothing.** Source, secrets, and data never reside at the hub.
5. **Standard wires.** Externals connect via MCP, ACP, and OpenAI-compatible LLM surface. Node-to-node uses the engine protocol over WS relay; Tailscale is an optional transport nicety, never a dependency.
6. **Trust zones.** Q and stewards run *where the data is*. Prompts and source do not cross trust boundaries for governance.
7. **Composability survives federation.** PTC (programmatic tool calling) is the execution model: one program fans out across nodes (`read@bunker`, `repo_state@office`), curates, returns once.

## 5. Engine core capabilities (build once; every role inherits)

- Cordis 4.0.2 plugin host (extensions are plugins; DSH plugin family mounts unmodified — proven in `src/core/plugins/native/dsh-harness.ts`).
- Tool registry with **typed canonical outputs + renderer split** (canonical value is the API).
- **PTC presentation** (`native | code | both`): `run_code` transport + generated SDK; worker code runtime (**Node ≥ 22.6**; shipped `@deepseek-ai/dsh-code-runtime-worker-thread` verified working on Node — Bun lacks `stripTypeScriptTypes`, so the DSH runtime path is Node-only). Align DSH package line: `@deepseek-ai/dsh-agent-tool-presentation` 0.1.1-rc.2 family.
- **Kernel catalog** (FTK essentials, in TS — NOT a Rust product): fused search (`locate`/symbol-aware windows), `plan_tests` impact mapping, read-memoisation, envelope+budget+handle outputs, per-launch telemetry (`~/.cascade/runs.jsonl`, `kind:"kernel"`).
- Policy/sandbox (approval, allow/deny/ask), skills + memory stores, sessions/transcript logs, background jobs, subagents/workflows/goals, git workspace manager.
- **Serve mode** surfaces: session API, MCP server, ACP server, OpenAI-style surface (LLM gateway role can ride the same process).

## 6. Registry / protocol surface (node-to-node, versioned)

Messages are the contract; versioned schema with a compat policy (mirror DSH session-log versioning discipline). Transports: outbound WS relay; tailscale mesh optional.

- `announce` — node/agent identity, capabilities, reachability (relay endpoint).
- `discover` — resolve `@agent` tags, capability queries, locate a gateway for repo R.
- `route` — which node owns a workspace/session; session pinned to the node whose filesystem owns the repo.
- `delegate` — call tool T on node N under policy P; bounded envelope reply; `expand(handle)` follows the same gate.
- `presence` — join/leave/heartbeat so the hub stays an *empty space of connections*.
- Identity: device/machine identity, scoped short-lived credentials, full audit of gated calls (agensis-agent auth model extended per-agent/per-resource).

## 7. Three-tier access model (agreed)

| Tier | Name | Semantics | Cost |
|---|---|---|---|
| 1 | **Relay (default)** | Files/tools served through relay directly, but **bounded**: envelope + anchors + handle. No raw content off-node. | ~0 model tokens |
| 2 | **Steward (always on)** | Engine-native dispatch policy: authz, redaction, scope, audit. `agent1_read_file` = steward-scoped tool name; the gate, not the brains. | ~1 ms |
| 3 | **Q (policy-invoked)** | Broker agent: reads the task, tools up the executor (node/agent choice, context assembly, scoped kits), supervises, returns distilled result. | model tokens + latency |

**Envelope (wire):** `{ ok, kernel/tool, summary, anchors[], payload?, truncated, handle?, delta?, cost }` — full content stays at the node.

## 8. Q — the Quartermaster (agreed model)

- Q is an **agent role** (not a code path): a model-backed broker with dispatcher tools (spawn/prep/supervise executors), its own memory + experience over time.
- Runs **near the data it governs** (bunker Q for bunker repo; vault Q for skills/context).
- Invoked **by policy**, never by default: cross-boundary requests, thin/device executors that cannot self-tool, agent-to-agent jobs, tasks tagged for Q. Bounded reads never meet Q.
- Tools up the executor: decides the right node/agent, assembles context, grants scoped kits, supervises, hands back the distilled result.

## 9. Fleet semantics (clashes)

- Sessions pin to the node owning the repo's filesystem; other nodes proxy control.
- **Git is the cross-location sync primitive** (worktrees/checkout modes). No live bidirectional file sync in v1.
- **Single-writer per workspace**; others see read-only or via commits. Leases only if concurrent writers are ever required.
- Merge discipline at commit time; conflict policy decided before the fleet layer ships.

## 10. Inference pool (LLM gateway)

- One surface over all provider keys/accounts (Hermes `:8642` precedent generalised).
- Per-account ceilings, fair queuing, per-request routing by policy, per-tenant usage telemetry (nobody silently burns another tenant's quota).
- Provider-agnostic; local engines (vLLM/SGLang/llama.cpp) plug in as providers.

## 12. Roadmap (real capability per phase; no spikes, no mocks, no shims)

| Phase | Scope | Exit criterion |
|---|---|---|
| **0** | Daemon consolidation (§11); collaborator becomes a client | One `@codesurf/daemon`; IDE consumes it as a dep; no drift |
| **1** | Agent-gateway serve mode: sessions + tool plane + PTC presentation + worker runtime on the engine; MCP/ACP/session surfaces | TUI and IDE both drive the same gateway; wire collapses to `[run_code]` + SDK in a PTC session |
| **2** | Relay + steward tiers: remote tool namespaces, bounded envelopes, audit | Two nodes exchange delegated bounded calls |
| **3** | Hub protocol (announce/discover/route/delegate/presence); device agents; skills/context served from data nodes | Remarkable Pro + phone appear in hub; `@`-tag addresses them; gateway sessions call device tools |
| **4** | LLM gateway pooling keys; fleet versioning/telemetry | Pooled inference live with ceilings + per-tenant telemetry |
